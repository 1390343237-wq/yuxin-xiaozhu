## 1. 顶层目标

做一个**跨端口可访问的线上工作台**（PC / 手机 / 平板浏览器均可打开），一站式管生活 + 工作。核心特征：

1. **单页应用 (SPA)**，按角色 / 场景分区，左侧导航 + 主区卡片流。
2. **数据双写（KV 为主）**：业务数据（订单、日志、营收、提醒、收藏等）**主写入走云端 KV**（`server/proxy-node.js` → `kv_store.json`），**同时尽力同步到腾讯文档**（MCP 写入受平台限制，可能仅落首列或不落盘，失败不阻塞主流程）。UI 顶部按同步状态显示徽章：`✓ 已落 KV + 已落文档` / `✓ 已落 KV ⚠ 文档同步失败` / `⚠ 仅本地缓存（代理离线）`。
3. **总览汇报**：每天 21:30 自动生成"今日复盘"+ 每周日 21:30 生成"本周复盘"，可在工作台首页一键查看。
4. **风控优先**：自媒体模块在生成文案 / 脚本时**必须**经过医疗敏感词 / 平台违禁词双过滤，被拦截的部分必须给出"替换建议"而不是直接丢弃。
5. **离线可用**：在没代理 / 没外网时所有功能使用本地 mock 数据正常工作，不白屏、不报错。

## 4. 民宿管理 · 详细规格

### 4.1 房型与房号映射（v1.0 权威表）

| 套房号 | 整租能力 | 分租卧室 | 备注 |
| --- | --- | --- | --- |
| **401** | ❌ 只分租 | 1, 2, 3, 4 | 4 间 |
| **1202** | ✅ 只整租 | — | 独立房号 |
| **1302** | ✅ 整租 | 5, 6 | 整租时占 5-6 |
| **407** | ✅ 整租 | 7, 8 | 整租时占 7-8 |
| **1502** | ❌ 只分租 | 9, 10, 11, 12 | 4 间 |
| **503** | ✅ 整租 | 15, 16 | 整租时占 15-16 |

**整租可选 = 4 套**（1202 / 1302 / 407 / 503）
**分租房 = 14 间**（1-4 + 5-6 + 7-8 + 9-12 + 15-16）
**总房态计数 = 18 个独立可售单元**（4 套整租 + 14 间卧室）

### 4.2 房态机（互斥锁逻辑）

**核心约束**：同一套房号在同一时段只能处于一种状态。

```
状态机：
  空置 (vacant) ─入/退→ 入住中 (occupied) ─退房→ 待打扫 (cleaning) ─完成→ 空置
                  ↘ 整租预定 (whole_booked)  ─退房→ 待打扫
                  ↘ 分租预定 (room_booked)   ─退房→ 待打扫
```

**互斥规则**：
- 当 407 处于「整租预定」时，**7 号、8 号房**自动显示为「已被套房占用」，不能再单独预定。
- 当 7 号或 8 号房存在未来 30 天内的「分租预定」时，**整租 407 不可下单**（UI 红色提示 + 后端拒绝）。
- 同理适用于 1302↔5/6、503↔15/16、401↔1-4。

**判定函数**伪代码：
```js
function canBookWhole(suiteId, dateRange, orders) {
  const roomIds = SUITE_TO_ROOMS[suiteId];         // e.g. 407 → ['07','08']
  return !orders.some(o =>
    roomIds.includes(o.roomId) &&
    overlap(o.checkIn, o.checkOut, dateRange)
  );
}
```

### 4.3 视图（4 个）

1. **房态看板**（默认）— 14 间卧室 + 6 整套，色块展示 30 天日历，可点击下单 / 改单 / 退单。
2. **订单流水** — 所有订单列表，支持按房号 / 状态 / 时间筛选。
3. **营收月报** — 当月所有订单金额、已收 / 未收、整租 vs 分租占比、成本（房租水电燃气）。
4. **当日任务** — 当天所有退房 / 打扫 / 入住 / 空置营销动作清单。

### 4.4 数据源（v1.0：KV 为主，文档尽力同步）

- **主写入**：通过 `Store.addOrder / addLog / setReport` 走 `server/proxy-node.js` 的 `/kv/*` 端点 → 落 `server/kv_store.json`。这是**唯一可靠**的写入路径。
- **尽力同步**：在主写入成功后，**异步**调用 `Sheet.appendOrders / appendLog` 把同一条记录同步到腾讯文档 `DYUdtRWlQTmxheW11` 下新建的 3 个 sheet：
  1. `订单操作日志` — 字段：操作时间 / 订单号 / 房号 / 动作 / 操作人 / 备注
  2. `营收成本月报` — 字段：日期 / 房号 / 类型(整租/分租) / 金额 / 已收 / 备注
  3. `当日任务清单` — 字段：日期 / 房号 / 任务类型 / 状态 / 完成时间 / 备注
- **只读数据源**：腾讯文档台账 `DYUdtRWlQTmxheW11`（【愈心小筑】入住情况）每 30 分钟轮询拉取一次最新订单、营收、成本。
- **失败处理**：文档同步失败不重试主流程，UI 顶部徽章降级为 `⚠ 文档同步失败`；运维侧通过 `calibrate_rooms.js` 定期比对 KV 与文档的差异做补录。
- **架构决策依据**：2026-08-03 实测发现 `set_cell_value` / `set_range_value` / `value_base64` 三种 MCP 写入方式均返回成功但读回为空，因此"文档唯一写入底座"在当前平台限制下不可行，必须以 KV 为真相源。

### 4.5 自动化

- 每天 21:00 抓取一次当日所有操作的腾讯文档写入情况，若有未同步项自动重试 3 次。
- 每周日 21:30 自动生成"本周民宿运营复盘"（见 §7 汇报系统）。

## 5. 自媒体营销 · 详细规格

### 5.1 目标

服务民宿，账号定位为"异地就医陪护 / 就医攻略 / 就医民宿"，日更 1-2 条。

### 5.2 三大子模块

| 子模块 | 功能 |
| --- | --- |
| 热点雷达 | 每天 09:00 / 14:00 / 20:00 自动抓取全网"异地就医""就医民宿""就医攻略""陪诊"相关话题（小红书 / 抖音 / 微博 / 知乎 / 百度），按热度 + 与民宿匹配度评分 |
| 文案工厂 | 选择一条热点 → 选平台（小红书 / 抖音）→ 选侧重点（位置优势 / 房型展示 / 陪护故事 / 季节主题 / 病种专题）→ 一键生成文案 |
| 风控过滤 | 文案生成后必须经过双层过滤（详见 §5.4） |

### 5.3 文案模板侧重点（v1）

| 侧重点 | 小红书模板 | 抖音脚本模板 |
| --- | --- | --- |
| 位置优势 | "天坛医院 5 分钟"系列 | 步行实拍 + 时间戳 |
| 房型展示 | 9 图轮播 + 价格 + 床位 | 一镜到底 + 字幕 |
| 陪护故事 | 患者故事 + 房间细节 | 第一人称叙述 + BGM |
| 季节主题 | 夏季空调 / 冬季暖气实测 | 体感温度对比 |
| 病种专题 | 心脑血管 / 肿瘤 / 骨科专版 | 专家科普 + 民宿实拍 |

### 5.4 风控（最关键）

**两层过滤，缺一不可：**

**第一层：医疗敏感词**（医疗行业硬规则）
- 禁用：治愈、根治、痊愈率、成功率、xx 天见效
- 提示替代：可以说"有助于""可能改善""有案例显示"
- 禁用具体疾病 + 具体疗效的组合（除非有资质证明）

**第二层：平台违禁词**
- **小红书**：医美 / 医疗 / 药品 / 保健品 4 大类全词库；诱导加微信 / 留电话；"最便宜""全网最低"等绝对化用语；未认证医疗账号发医疗内容。
- **抖音**：医疗内容必须加"内容仅供参考"水印；禁止承诺疗效；禁止引导站外交易；禁止对比贬低同行。

**拦截流程**：
1. 生成文案 → 跑双层过滤
2. 被命中 → **不丢弃**，而是：
   - 红色高亮命中词
   - 给出 3 个替换建议
   - 用户可一键采纳或手动改
3. 全通过 → 进入"待发布"队列，记录生成时间 + 平台 + 侧重点

### 5.5 数据源

- **热点抓取**：web search 技能（每天 3 次）
- **风控词库**：内置 v1 词库 + 用户可在"设置 → 风控词库"自定义补充
- **文案记录**：本地 KV（不必写腾讯文档），用户在"待发布"队列点"已发布"后归档到"已发布"页
